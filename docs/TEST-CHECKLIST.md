
# Roast Duck Kitchen / 烤鸭小店

## Demo 功能测试与验收清单


## 1. 测试目的与范围

本清单用于验证《Roast Duck Kitchen / 烤鸭小店》当前 Demo 的功能完整性、操作正确性、评分准确性及基本运行稳定性。

### 1.1 当前 Demo 目标

玩家能够完成以下流程：

启动游戏 → 点单 → 烤制 → 片鸭 → 料理 → 卷制 → 完成订单 → 结算评分 → 返回工作区

当前只要求完整处理一张订单。

### 1.2 本轮测试范围

- 游戏启动与基础界面
- 点单区订单生成与展示
- 烤炉区烤制与片鸭
- 料理台配料选择与卷制
- 交付与结算场景
- 三站评分及综合分
- 顾客表情、评价与铜钱反馈
- 工作区切换与数据传递
- 鼠标、键盘及手势输入
- 异常操作与重复操作
- 基本运行稳定性
- 单订单 Demo 重新开始

### 1.3 暂不纳入当前 Demo 验收

以下功能属于后续扩展范围，不作为本轮必须通过的测试：

- 多顾客同时等待
- 多订单并行制作与切换
- 五单营业流程
- 营业结束汇总页面
- 成功与失败条件
- 多订单营业奖励累计
- 复杂品尝、咀嚼及递餐动画

相关功能可在后续整合阶段追加测试。

### 1.4 测试状态说明

- `[ ]` 未完成测试或尚未通过
- `[x]` 已执行且符合预期
- `PASS` 测试通过
- `FAIL` 测试失败
- `BLOCKED` 功能尚未实现或依赖未就绪
- `N/A` 当前版本不适用

注意：GitHub 复选框只记录通过的项目。失败、阻塞或不适用的测试应保持未勾选，并在测试记录中注明状态。

## 7. 评分算法测试

### 7.1 点单评分

当前试运行公式：

点单分 = 剩余耐心秒数 ÷ 120 × 100

| 剩余耐心 | 预期点单分 |
|---|---|
| 120 秒 | 100 |
| 90 秒 | 75 |
| 60 秒 | 50 |
| 30 秒 | 25 |
| 0 秒 | 0 |

- [ ] TC-097：120 秒对应 100 分。
- [ ] TC-098：90 秒对应 75 分。
- [ ] TC-099：60 秒对应 50 分。
- [ ] TC-100：30 秒对应 25 分。
- [ ] TC-101：0 秒对应 0 分。
- [ ] TC-102：点单分显示与实际传入的剩余耐心一致。

### 7.2 烤炉评分

- [ ] TC-103：未熟对应 40 分。
- [ ] TC-104：适熟对应 100 分。
- [ ] TC-105：烤焦对应 0 分。
- [ ] TC-106：结算使用的是实际取出时记录的火候结果。

### 7.3 料理评分

五种食材分别检查，每项正确得 20 分。

饼皮自动提供，不参与五项配料评分。

| 正确项目数量 | 基础料理分 |
|---|---|
| 5 | 100 |
| 4 | 80 |
| 3 | 60 |
| 2 | 40 |
| 1 | 20 |
| 0 | 0 |

- [ ] TC-107：五项全部正确时基础料理分为 100。
- [ ] TC-108：四项正确时基础料理分为 80。
- [ ] TC-109：三项正确时基础料理分为 60。
- [ ] TC-110：两项正确时基础料理分为 40。
- [ ] TC-111：一项正确时基础料理分为 20。
- [ ] TC-112：零项正确时基础料理分为 0。
- [ ] TC-113：漏加订单要求的食材，该项不得分。
- [ ] TC-114：多加不需要的食材，该项不得分。
- [ ] TC-115：多加食材时，额外扣分按最终确认规则执行。
- [ ] TC-116：配料错误仍允许正常结算，不弹出阻断交付错误。

注意：额外扣分的具体数值和最低分限制尚未确认。TC-115 在规则确认前标记为 BLOCKED，不自行假定扣分数值。

### 7.4 综合分

综合分 = round((点单分 + 烤炉分 + 料理分) / 3)

| 点单 | 烤炉 | 料理 | 预期综合分 |
|---|---|---|---|
| 100 | 100 | 100 | 100 |
| 75 | 100 | 100 | 92 |
| 50 | 100 | 100 | 83 |
| 50 | 40 | 60 | 50 |
| 0 | 0 | 0 | 0 |

- [ ] TC-117：三站分数正确参与平均。
- [ ] TC-118：综合分按照约定进行四舍五入。
- [ ] TC-119：综合分显示与计算结果一致。
- [ ] TC-120：同一订单不会重复累计分数。
